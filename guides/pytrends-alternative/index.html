pytrends, the unofficial Python client for Google Trends, is archived (read-only) on GitHub, and Google often answers it with "TooManyRequestsError: The request failed: Google returned a response with code 429", especially from servers and notebooks. Google Trends Scraper on Apify returns the same data (interest over time, interest by region and city, top and rising related queries, and what's trending now) from a hosted service that rotates IPs and retries for you. You call it from Python in a few lines and pay $1 per 1,000 keyword reports. If your code already uses pytrends, the quickest fix is pytrends-cloud, a free open-source drop-in replacement: change one import (from pytrends_cloud.request import TrendReq) and the same calls return the same DataFrames.

FAQ

Do I have to rewrite my pytrends code?

No. pytrends-cloud (github.com/retracn/pytrends-cloud, MIT) mirrors pytrends' TrendReq: change the import, set APIFY_TOKEN and keep the rest. It returns the same pandas DataFrames.

Why does pytrends return 429 Too Many Requests?

Google rate-limits the unofficial endpoints pytrends calls, per IP address. Cloud and shared IPs hit the limit fastest, and pytrends has no built-in IP rotation, so sleeping between calls only helps for a handful of keywords.

Is pytrends still maintained?

No. The GeneralMills/pytrends repository on GitHub is archived (read-only), so fixes for Google's changes won't be released. The last release on PyPI is 4.9.2.

Can I keep my pandas code?

Yes. Each keyword report has a timeline list of points with date and value, so pandas.DataFrame(report['timeline']) gives you the same date and interest columns as interest_over_time().
